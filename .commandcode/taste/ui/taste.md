- Colors in the design system are semantically loaded and must not be used interchangeably: the accent/interactive color (teal) is reserved for clickable elements/links (e.g., "Buka di Google Maps"), primary content uses charcoal, and descriptive metadata (location) uses muted gray. Rendering a non-interactive metadata value in the link color can make it look clickable and is something the user may flag ("warnanya jangan gitu deh") — when picking a color, first determine what the element semantically is, cross-check the Figma reference, and keep accompanying icons the same color as their text. However, the scheme is not absolute: an explicit color preference from the user overrides it — in the wishlist detail they wanted the time in the title color (charcoal) and the notes in the secondary color, the same muted gray as the "TAUTAN" label ("harusnya catatan warnanya secondary kaya label TAUTAN"). The user iterates on color choices and expects the latest correction to win — they first asked for notes in teal, then explicitly walked it back to secondary/muted ("sorry, harusnya..."), so the agent should not treat an earlier color preference as final once a correction arrives. Confidence: 0.8

- Empty-state layouts must be vertically centered — when a pipeline/list (e.g., the itinerary timeline, the voting tab) has no items, the container must use `justifyContent: 'center'` so the empty content is centered in the available space rather than stranded at the top ("justify content pipeline itinerary kalo kosong harusnya center", "seharusnya empty state content tab voting justify center", "tolong perbaiki empty state itinerary"). Implementation detail: when the empty state renders inside a `ScrollView`, centering only works if the ScrollView's `contentContainerStyle` includes `flexGrow: 1` — otherwise a `flex: 1` + `justifyContent: 'center'` empty container collapses to content height and the content sits at the top. This exact root cause + fix recurred in both the itinerary tab and the voting tab, so the agent should audit every tab/screen with a scrollable empty state for the missing `flexGrow: 1`. The empty-state trigger must also key on actual data presence (e.g., `activities.length === 0`) rather than derived structure that always exists — a date range always yields ≥1 day, so a `!currentDay` branch is nearly unreachable for dated trips and the real "Belum ada aktivitas" state never shows; remove stray top padding offsets so the centering is exact. Confidence: 0.82
