When the design shows a screen, use `router.push` to a dedicated route; when it shows a sheet/modal, use a sheet. Confidence: 0.85

"Pastikan fungsionalnya berfungsi, pastikan berhasil e2e seperti di workflow dan design" — both are non-negotiable and equally important. Confidence: 0.9
- The Figma design files are the authoritative spec, but the user explicitly acknowledges the design may contain minor errors and authorizes the agent to apply its own judgment — implement what is correct when the design is wrong, rather than replicating design flaws blindly ("Design yang ada di figma saat ini bisa saja ada kesalahan minor, jadi hati-hati dan tetap terapkan yang menurut mu benar saat designnya ada kesalahan"). Confidence: 0.8
- Every UI element on screen must have a clear design justification — unexplained/unauthorized buttons, icons, or components that don't appear in the Figma design are bugs that must be removed or corrected. "Button gajelas" (unclear/unnecessary buttons) are specifically called out as unacceptable. Confidence: 0.7
- Prefers reusing existing Figma source code directly (the `.tsx` component files under `figma/src/app/components/`) rather than recreating design assets from scratch — the agent should extract and adapt the existing Figma components, not author new ones. Confidence: 0.85
- On web, react-native-web's `Alert.alert` is a no-op stub — this has bitten the user three times (logout, "Hapus Perjalanan"/delete trip, and now "Keluarkan anggota"/remove member) where the confirm dialog never appeared on web and the destructive action silently never ran. The resolution must NOT be browser-native `window.confirm` either — the user explicitly rejected that as "kurang proper" (not proper enough) and expects a proper custom confirmation modal matching the Figma design (e.g., a shared reusable `ConfirmModal` component following `ConfirmDialogModal` / Screen95 TripDelete: centered card, icon in tinted 48px box, Batal outline + Hapus danger buttons, loading spinner during submit) that works identically on web and native. When a destructive action "doesn't work", check the confirmation path first on web, but implement it as a design-matched modal, not a platform confirm/alert workaround. Confidence: 0.95
- Layout elements must fit their natural content height — never stretched by default `alignItems: 'stretch'`. This applies to grid cards (2-column wishlist cards: `alignItems: 'flex-start'` on the row + explicit width instead of `flex: 1`) AND chips inside horizontal ScrollViews (add `alignItems: 'center'` on `contentContainerStyle` + `flexShrink: 0` on each chip, otherwise all chips stretch to the tallest one). User reported this class of bug three times ("heightnya jadi tinggi banget", "height tagsnya masih tinggi banget", "margin vertical di tagsnya berlebihan" — excessive vertical margin/padding in tag chips). Confidence: 0.9
- A horizontal `ScrollView` itself defaults to `flexGrow: 1` in React Native, so even with correctly-sized chips it expands to fill the entire remaining screen height, leaving large empty space above/below the row (chips appear "isolated" in the middle of empty area). The ScrollView must get `flexGrow: 0` on its own `style` (e.g., `tagChipsScroll: { flexGrow: 0 }`) so its height wraps content — this was the actual root cause of "margin vertical di tagsnya berlebihan" after the chip-stretch fix alone proved insufficient. Confidence: 0.85
- Popover/context menus (edit, delete, convert, kebab ⋮) must be rendered as overlays that are never clipped or covered — not inside cards whose `overflow: 'hidden'` clips them (reported as "action delete dan edit wishlist jadi hilang"), and the owning card must get elevated z-index/elevation while its menu is open so adjacent cards don't overlap it (reported as "pop up kebab menu voting ketiban sama ui card voting"). Confidence: 0.8

- When conditionally rendering with `x && <Component>`, never let `x` be a value that can be an empty string — react-native-web renders `''` as a text node child of a `<View>` and throws "Unexpected text node" (native silently ignores it, so the bug only surfaces on web). Error-message variables that are `''` when valid must use an explicit ternary (`{titleError ? <AlertCircle /> : null}`). Confidence: 0.75
